AI-Quiz (PigZap) — Full-Stack Audit Report

A static review of the entire monorepo: NestJS 10 + Postgres/Redis API, Next.js 15 frontend, Docker/Dokploy + Cloudflare deployment, and the CSV content pipeline — covering what's missing, what's broken, what's cosmetic, and what security is absent for a live site.

1. Executive summary

This is a much better-built codebase than its age and scope suggest. It is not a prototype: 20 wired NestJS feature modules, a real database layer with 30+ migrations, RBAC plus a global default-deny auth guard, refresh-token rotation, Redis brute-force lockout, an idempotent content-push tool, an automated nightly DB backup with a restore test, and a Next.js frontend with a coherent SEO layer, consent-gated analytics and 32 Jest test files.

The problems are not "the app is broken". They are the classic gap between a well-engineered product and a production-hardened service.

2. High-severity findings (fix before launch)

H1 Public endpoints return the answer key SEC-03

Image-riddle, quiz-MCQ and riddle-MCQ public reads return full entities — including answer, correctAnswer, correctLetter and options. Public image-riddle reads return the literal answer column; GET /quiz-mcq/subjects/:slug/questions and GET /quiz-mcq/questions/:chapterId are @_Public() and select all columns.

Impact: the whole answer key is scrapeable with one unauthenticated loop, and it contradicts the deliberate masking the comments module implements.
Fix: public DTO projections that omit answer columns; grade server-side (the duels module already does).

H2 Hardcoded JWT secret fallback SEC-01

auth/auth.module.ts:26 uses configService.get('JWT_SECRET', 'your-secret-key'), so any non-production environment signs tokens with a publicly known secret.
Fix: getOrThrow('JWT_SECRET') and fail fast for every non-dev environment.

H3 Internal error messages leaked in production SEC-02

common/filters/http-exception.filter.ts:63 returns exception.message for non-HttpException errors unconditionally; only stack/details are dev-gated. Raw TypeORM/driver text (constraint names, SQL fragments) reaches clients.
Fix: map non-HTTP errors to a generic message in production; log the real one server-side.

H4 Content push aborted; conflict gate dead for most types BE-08

The quiz push log stops at questions: created 6450/11541 then exits 2 with no "Done." — ~5,000 questions unpushed. The persisted state file has only subjects/riddle-categories/chapters; there is no questions/riddle-mcqs/dad-jokes/image-riddles baseline, so "live edit wins" conflict detection can never fire for those types.
Fix: re-run npm run content:push -- --apply to completion and verify the state file; persist state incrementally.

H5 Deploy scripts' DB backup is broken OPS-01

deploy.ps1:230 / deploy.sh:200 target container quiz-postgres-prod, which does not exist (prod container is quiz-postgres); PowerShell > also writes UTF-16, corrupting a stdout dump. This is the path update runs before redeploying.

H6 Prod publishes app ports on all interfaces (origin bypass) OPS-04

docker-compose.prod.yml maps 4004:3012 and 3001:3010 with no host IP, so anyone can hit the origin directly and bypass Cloudflare (TLS, WAF, rate limiting). The "restrict origin to Cloudflare IPs" item is still pending.
Fix: drop the mappings or bind loopback; restrict the firewall to Cloudflare IPs on 80/443.

H7 Deploy scripts health-check the wrong host ports OPS-02

Scripts probe localhost:3012/3010, but prod publishes 4004/3001 → status/start/restart always report "Unhealthy", masking real failures.

H8 Frontend: JWT in localStorage + no CSP

User and admin JWT + refresh pairs live in localStorage/sessionStorage (XSS-readable), and next.config.mjs ships no Content-Security-Policy despite three inline-script surfaces (theme bootstrap, GA init, JSON-LD).
Fix: move refresh tokens to HttpOnly; Secure; SameSite cookies long-term; add a strict CSP with nonces now.

H9 Credential rotation still pending; live OAuth secret on disk

apps/backend/.env holds a live Google OAuth client secret; root .env and backend .env share one dev JWT_SECRET; plan/STANDARDS.md:56 and TODO.md record that rotation (+ possible git-history scrub) is still pending before any production deploy. Files are correctly untracked today, but the exposed values have not been rotated.

7. What's already good (keep doing this)

Verified strengths
  • Auth core: bcrypt cost 12; refresh tokens random 32-byte, stored only as SHA-256 hashes with 7-day expiry + rotation-on-use + server-side revoke; 15-min access tokens; Redis brute-force lockout; hashed one-time reset/verification tokens; enumeration-safe flows.
  • Authorization: global default-deny JwtAuthGuard as APP_GUARD with explicit @_Public() opt-outs; every /admin/* controller guarded with @Roles('admin'); IDOR checked on users/:id.
  • Transport & input: helmet, CORS allow-list, 1 MB/50 MB body-size split, global ValidationPipe (whitelist + forbidNonWhitelisted), javascript:/data: URL validator, parameterized SQL everywhere, 5 MB upload cap + MIME allow-list + sharp re-decode.
  • DB: synchronize off by default and forbidden in production; migrations auto-run on prod boot; optional SSL with rejectUnauthorized default true.
  • Content pipeline: env-file credentials (never argv), no secret logging, dry-run default, typed PUSH confirmation, natural-key idempotency, conflict detection, no deletes ever, 10-table allowlist.
  • Frontend: skip link + single <main>; global :focus-visible ring + reduced-motion; a genuinely correct focus-trapped Modal; consent-gated + anonymized GA; dangerouslySetInnerHTML safe at all three sites; normalizeExternalUrl() blocks javascript:/data:.
  • Deployment: multi-stage non-root images; prod DB/Redis not published; Redis password + healthchecks + restart: unless-stopped; nightly gzipped backup with a restore test; Cloudflare strict TLS + HSTS + HTTP/2-3; TRUST_PROXY=true behind the proxy.
