- **Riddle MCQ module is fully built out** and matches its plans: backend at `apps/backend/src/riddle-mcq/` has the exact multi-service split the refactor plan prescribed (question/subject/category/bulk/bulk-actions/import/stats services, slug + csv-export utils, difficulty & pagination validators), and the frontend has `apps/frontend/src/features/riddle-mcq/` plus app routes `/riddle-mcq`.
- **Refactor Priority 1 is genuinely complete** — `riddle-mcq-bulk-actions.service.ts`, `riddle-mcq-import.service.ts`, `utils/slug.util.ts`, `utils/csv-export.util.ts` all exist exactly as `RIDDLE-MCQ-REFACTOR-PLAN.md` claims.
- **Rename plan largely executed** — entity files are named `riddle-subject.entity.ts` / `riddle-category.entity.ts`; verification needed on class names, but the file layout matches the plan's end state.
- **Quiz UX documented = quiz UX built**: `/quiz/play`, `/quiz/timer-challenge`, `/quiz/practice`, `/quiz/practice-mode`, `/quiz/results`, `/quiz/challenge` (redirect shim to timer-challenge) exist in `apps/frontend/src/app/quiz/`, matching `quiz-user-experience.md`'s mode list.
- **Feature parity audits converged**: the verification report corrected the initial audit against real code (e.g., confirming `getStatusCountsBySubject` in quiz.service.ts and CSVPreview existence), so the _verification_ doc is trustworthy input for gap-closure work.
- **PORT-REFERENCE.md and assistant-rules.md port data are accurate** where they overlap with code: `ports.ts:18-27` defaults (3012/3010/5432/6379) match both docs.
- **Reference implementation preserved**: `quiz-reference/` is a complete, runnable vanilla-JS/CSS demo of the product concept — 10 subjects × chapters × 3 difficulty levels, timed/untimed modes, riddles game, localStorage persistence, SPA routing, animation polish — serving as the design/UX source of truth.

## 6. How It Works (summary)

The documentation set tells a coherent story in three layers. **Layer 1 — philosophy**: `true-ideal-approach-plan.md` and `multiple architecture format.md` define the target engineering religion: URL as sole UI state, backend as single source of truth, React Query as the cache layer, ≤200-LOC components/services. **Layer 2 — plans**: the `docs/` tree turns that philosophy into concrete build orders — `feature-list.md`/`implementation-detail.md` specify the (completed) quiz MCQ system endpoint-by-endpoint, and the three riddle-mcq plans (backend, admin, implementation) clone the proven quiz architecture onto a Category→Subject→Riddle hierarchy with riddle-specific rules (option count scales down with difficulty; Expert level is free-text with required `answer`; hint/explanation fields). **Layer 3 — audits**: once both modules existed, `FEATURE_PARITY_AUDIT(_VERIFICATION).md` and `NAMING_INCONSISTENCY_AUDIT.md` measured drift between them, and `RIDDLE-MCQ-REFACTOR-PLAN.md`/`RIDDLE-RENAME-PLAN.md` queue the cleanup. Operational truth lives in `DEPLOYMENT.md` + `PORT-REFERENCE.md` + `assistant-rules.md`.

`quiz-reference/` is the pre-Next.js prototype: a hash/history-routed static site where `quiz-data.js` holds in-browser question banks for 10 subjects, `quiz-logic.js`/`quiz-timer.js` implement normal/timed/practice play with pause rules, `riddles-logic.js` prototypes the riddle game (chapters, timer/no-timer mixes), `quiz-storage.js` persists sessions to localStorage, and `test-all-subjects.js` validates the data. Its CSS folder is the visual spec (colored chapter cards, emoji effects, bubbles, mobile responsiveness) that the Tailwind-based app reimplemented. Nearly every user-facing feature demonstrated there has since been re-implemented in the Next.js/NestJS app (quiz play incl. timer-challenge and practice routes, riddle-mcq module, jokes page, image-riddles page, results); what has _not_ carried over is the reference's path-style clean URLs (replaced by query-param state, deliberately, per the ideal-approach doc) and its client-side self-test harness for content completeness.
